# Plenum Coding Superpowers — company-specific method

**Source:** [obra/superpowers](https://github.com/obra/superpowers), MIT license, reviewed commit `22f0b463e7a5e579904dd6211a520321035526f7`. This skill ADAPTS engineering principles; it is not the full upstream plugin, and merely existing in this repository does not enable an external coding agent.

1. **Inspect first:** Read live project `AGENTS.md`, ledger, current issue, source tree, existing tests and original upstream. Reuse source before proposing a new abstraction.
2. **Specify completion:** Convert the founder's objective to an observable deliverable, constraints, permissions and review criteria; keep legal/IP and confidentiality requirements explicit.
3. **Prefer one complete change:** Choose the smallest integration that fills an ACTUAL capability gap; do not create incremental PRs merely to rerun successful fixtures.
4. **Plan before editing:** Describe files to change, what will be reused, one rollback route and only the necessary test of genuinely changed behavior.
5. **Fix only observed defects:** If a new change fails a new assertion, read the failure, correct the root cause and rerun the focused assertion. Do not run mature model/simulation suites repeatedly under unchanged inputs.
6. **Verify outcome and report:** Independent readback of actual resulting commit/PR/task artifact. Distinguish syntax-only code, reviewed proposal, tested application and live deployment. Never claim a draft is production-ready.
7. **Approval gate:** External emails, deployments, payments, credentials, merges to protected repositories, new cloud costs, and publication require specific founder authorization and normal repository protections.
