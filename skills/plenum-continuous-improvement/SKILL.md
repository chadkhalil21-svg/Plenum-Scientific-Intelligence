# Evidence-limited make → evaluate → learn → reuse
Adapt ideas from Andrej Karpathy's MIT `autoresearch` project (https://github.com/karpathy/autoresearch) and from the 6 October 2026 Duncan Rogoff video. These are methodological references, not packages installed on every worker or evidence that AGI was achieved.
- Choose an existing approved output and ONE measurable acceptance test, plus a frozen baseline. Do not re-run upstream library qualification.
- Let the existing original specialist produce the next candidate ONLY for a real founder-requested task.
- Have Goldfish inspect the artifact, primary citations, and objectively measurable result in fresh context. A model critic's preferences alone do not verify improvement.
- Preserve a short factual lesson, artifact identifier, known failures, metrics and decision in original Elephant storage, not a huge concatenated chat or opaque chain of thought.
- Promote only if output meets or exceeds the original acceptance rubric without new cost, fact drift, private data disclosure or rights problems. Otherwise revert or mark incomplete.
- Repeated research or design loops are allowed only where legally permitted, project-related and within approved no-new-charge runtime quotas. GitHub Actions is NOT a permanent model host.
