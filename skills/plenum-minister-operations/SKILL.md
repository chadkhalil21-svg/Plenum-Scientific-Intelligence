# plenum minister operations

**Apply when:** When decomposing founder objectives into work packages and supervising delivery.

## Continuity preflight (reuses existing free systems)
Before creating work packages, retrieve the founder's existing private Google Drive **Plenum Industries | Master Control Ledger** (when this worker has authorized access), especially the latest Conversation Register, Context Protocol, Action Register and linked original GitHub/provider records. Prefer direct current provider evidence to older summaries. Separate DONE (reported), VERIFIED, PENDING and OPEN. A source GitHub issue/CI success is not user-facing completion. If access to private Drive is absent, state **NO PRIVATE LEDGER ACCESS**; never infer private context from public GitHub or ask founder to repeat already available information. A new private ChatGPT Plenum Continuity skills plugin has been created to guide ordinary chat retrieval but its presence does not grant this GitHub worker external account permissions or auto-ingest conversations.

Existing memory components: langgraph==1.2.20, langgraph-checkpoint-sqlite==3.1.3 are already optional Plenum dependencies; keep their durable thread checkpoints. For personal cross-chat retrieval, the private Drive index remains authoritative; do not publish it to research-memory. Optional free MIT @modelcontextprotocol/server-memory can support local MCP clients only when they have an owner-approved persistent private disk. Do not install or host Mem0, Graphiti, or Letta as duplicate infrastructures absent an evidenced need. See docs/PLENUM_ELEPHANT_GOLDFISH_FREE_CONTINUITY.md.
## Procedure
1. Read original live Plenum ledger, accepted outputs and blockers before assignment.
2. Define outcome, scope, single accountable owner, bounded tool permissions and measurable completion for every work package.
3. Route deterministic tasks with existing GitHub/n8n/standard code; use agent reasoning only for genuinely ambiguous decisions.
4. Delegate work across five divisions without treating catalogued profiles as running staff.
5. Keep durable task IDs, pause reasons, dependencies, and verified evidence. Notify founder only when approval or decision is necessary.
6. Report completed, blocked, next, and the highest-impact business constraint rather than counts of bots or tasks.

## Required deliverable
Top 3 decisions or blockers | Accepted outcomes | Assigned worker and evidence | Next action and founder approval.
