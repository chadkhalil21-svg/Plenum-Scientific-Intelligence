# Upstream durability integration

Adopt DBOS 3.7.0 (MIT), Litestream 0.5.18 (Apache-2.0), and the Ubuntu signed-package pgBackRest distribution (MIT) using only the existing standard public ephemeral runner allowance. No DBOS Cloud, remote tracing, object-storage account, persistent server or model/provider calls.

The candidate routes the exact independently accepted PR #912 public archive (artifact 15002230423, pinned SHA-256) through an actual DBOS durable two-step receipt workflow. Acknowledged step one is persisted, then the process is deliberately terminated. Litestream backs up the committed SQLite system database to a local file replica, verifies a trial restore, and seals its manifest. GitHub attestation plus exact-byte verification gates the separate-runner restore and DBOS continuation of the original workflow ID; immutable step-one receipt rejects duplicate execution. An actual PostgreSQL 16 cluster seeded with the same accepted public mission rows uses pgBackRest stanza-create/check/full backup/verify/restore into an absent data directory. Comparison against the independent expected rows validates recovery.

This is an isolated adoption candidate, not production replacement, and not an extra agent framework. Keep #913 and its native workforce/hidden answer checks untouched. DBOS may re-execute unacknowledged steps; never wrap an ambiguous model/provider or external effect in automatic retry. Native Paperclip database and LangGraph SQLite production adapters are not switched to these tools until their exact versions and full native mission gates are independently qualified. The pgBackRest fixture is real PostgreSQL but not the native Paperclip cluster. GitHub archive retention is bounded; pinned #912 source may expire, at which point fail closed until an independently verified replacement is reviewed. No owner-private data or credentials in public CI. Physical bare-metal deferred. Real account billing remains separate from no paid services initiated.
