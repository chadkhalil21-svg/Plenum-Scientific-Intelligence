# Plenum | Free Hosting for Named AI Workers
**Decision basis:** Official provider pricing and runtime limitations checked 2026-11-10. Free tier ≠ unlimited costs, uptime or model intelligence. **No new cloud host or billing setting was created by this comparison.**

|---|---|---|---|
| **Oracle Cloud Always Free A1** | Current Always Free documentation describes approximately **2 Arm OCPUs and 12 GB RAM** for a full month, with home-region networking and storage quotas. | **Best free candidate:** potentially a private Hermes gateway and a small CPU Qwen/Ollama model after benchmarks. | Requires new eligible Oracle account (typically card + phone), A1 stock can be exhausted, underused VMs can be reclaimed. Never accept PAYG overage by mistake. |
| **Google Compute Engine e2-micro** | One eligible e2-micro VM/month, ~1 GB RAM, 30 GB standard disk in us-central1/us-east1/us-west1. | **Possibly for gateway only**, not capable autonomous local model worker; model would need an independently free permitted provider. | Separate **external IPv4 currently charges ~$0.005/hour** (save by no external IPv4, but outbound Telegram access then needs a no-cost verified networking path). **Preferred strict-$0 order:**
1. Use **existing GitHub issues/actions** for public tasks and outbound status, at no *new* hosting cost.
2. For a genuine private always-connected chat gateway, check whether an **existing owner-controlled machine/VM** is already running and has spare capacity; *reuse that first*. If not, **Oracle Always Free A1** is the most practical candidate subject to availability and secure account setup. Limit initial bot gateways to 3, not 10 always-running model processes.
3. If already on Google Cloud, use **Cloud Run only as a request-triggered webhook** or an **e2-micro** only after calculating separate IPv4, egress, secrets and disk charges. Do not create or upgrade a paid service without explicit cost authorization.
4. When private bots exist, use **encrypted persistent volume and one owner-controlled credential store**, with user/sender allowlists and a separate identity per bot. Google Cloud Secret Manager's current monthly free allowance is **six active secret versions and 10,000 accesses shared by billing account**, if remaining after existing browser secrets. It is *not* an inexhaustible free enterprise password vault. Native provider OAuth scopes and customer consent are separate.
5. Keep Plenum's original Deep Agents Chief, n8n automations and science memory; Hermes is a **user-facing communication gateway**. Neither Telegram nor a free VM grants access to Gmail, Stripe, Google Drive, bank accounts, browser cookies or ChatGPT connector tokens.

## Additional candidate independently discovered on November 10: redu.cloud (new provider)

[redu.cloud official free-hosting terms](https://redu.cloud/free) now advertise **one always-on Ubuntu VM (1 vCPU, 2 GiB RAM, 10 GiB storage)** and **one always-on private PostgreSQL VM (1 vCPU, 1 GiB RAM, 2 GiB storage)**, £0 advertised price with one allocation per account, subject to capacity. **New account must add a card within seven days or free resources are deleted**, and free outbound bandwidth is only **5 GiB/month**. It offers a hard-budget mode, but its own current terms warn that overruns may delete free resources rather than merely stop further requests. Management is described as **MCP-only**, so check that the user's actual connected client can establish the requisite OAuth session before choosing it.

**Assessment:** Interesting `$0` always-on alternative for *one lightweight Hermes WhatsApp gateway* if the provider actually supports the Node/Baileys runtime, persistent WhatsApp session directories, secure inbound/outbound connectivity and account authorization. **Not yet demonstrated:** reliability, the precise SLA, operational maturity, compatibility with Hermes multi-profile memory or ongoing free allocation. Its 2-GiB VM is **not** a credible host for ten capable local model processes. Do not send personal/business WhatsApp keys to a novel provider before a temporary, nonsecret pilot proves persistence and sender isolation.

Other source-verified secondary possibilities: [Vultr free-tier early-access 1 vCPU/512 MiB/10 GiB](https://www.vultr2.com/resources/faq/) **only for selected accounts**, and [serv00 free SSH/web hosting](https://www.serv00.com/) is **not a general-purpose VPS** (terms restrict services to web/email/Git-related purposes and can block excessive resources). [Koyeb free instance](https://www.koyeb.com/docs/reference/instances) sleeps after one idle hour and has no persistent volumes. None is a verified stable enterprise-class replacement for an available Oracle Always Free A1.

## November 10 provider recheck: strict zero-cost hosting and real WhatsApp groups

This updates the original comparison without claiming a free host has been allocated. **Primary: Oracle OCI Always Free A1 (2 OCPUs/12 GiB RAM under the current 1,500 OCPU-hour/9,000 GB-hour monthly quotas)** for a *persistent dedicated WhatsApp Baileys* host only if the founder accepts the unofficial bridge's account-restriction risk, registers a **separate WhatsApp number** and obtains Oracle capacity. Free quota and instance reclaim are not uptime guarantees. Model inference must also be free/locally hosted and measured. The official Hermes `advanced-delegation` route can share one gateway process while selecting nine specialist profiles; one WhatsApp bot identity is still **one** contact, not nine independent phone numbers.

**Official Meta WhatsApp Business DM:** Google Cloud Run `min-instances=0` is the simpler eligible free-tier **HTTP webhook** option when an authorized Meta Business app and business number exist. The Hermes `whatsapp_cloud` adapter currently accepts DMs, **not groups**, and its worker/model state must survive scale-to-zero elsewhere. Never put the Cloud API gateway on the existing private browser Cloud Run worker or assume it runs continuously with idle CPU.

**Provider-specific exclusions for sustained group gateways:** Koyeb's 512 MB/0.1 vCPU free *web* instance sleeps after one hour without traffic and has no persistent volume; Render Free sleeps after fifteen minutes and loses local data on restart; Railway Free grants only $1 monthly usage credit; Vercel Hobby is for noncommercial personal projects; Netlify Free is credit-limited; Cloudflare Workers Free (100,000 requests/day, ~10 ms CPU/request) and AWS Lambda/Azure Container Apps are webhook/short-job tools, not persistent Python/Node WhatsApp bridges; Hugging Face free CPU spaces sleep and some compute-space creation is restricted. **Fly.io, Hostinger, and most ordinary VPS offers are not perpetual free compute plans.**

**GCP caution:** e2-micro's VM CPU is eligible for no charge within its limit, but a normal attached external IPv4 carries roughly `$0.005/hour × 720 hours = $3.60/month` before egress and other charges. A project billing budget is an alert, not a strict hard spending cap. An e2-micro without reachable networking or a free outbound route is not a working WhatsApp gateway.

**No new provider account, WhatsApp number, pairing QR, login session, privileged token, VM, Cloud Run webhook or $0 uptime proof was found/created by the research.** The existing ChatGPT Github issue command channel and verified LangGraph/Qwen Chief tasks remain available; Hermes messaging requires an account and host.
