# Owner-native cold recovery candidate
This is a conservative **unqualified** owner-runtime implementation, not a production result. It is not callable from public GitHub Actions. It never creates a server or volume, starts the production container, prints credentials, or sends backup bytes to GitHub. Requires a pre-existing quiesced stopped source named plenum-paperclip-production, actual production volume of the same name, and an existing stopped network-none plenum-paperclip-recovery container with its own empty writable volume of the same name, no published ports, restart policy no, same pinned Paperclip image, and a reviewed exact checkout mounted read-only at /plenum. The operator must independently verify source/target configuration, image, current source commit, actual production provenance, compatible native dependencies, provider isolation, billing/free capacity, and original qualification readback. The script verifies file digests and native PostgreSQL storage markers, rejects links and special files, requires a separate empty target, starts only that existing isolated target for native readback, stops it afterwards and leaves its recovered volume intact. The source remains stopped; operator controls its safe resumption. No automatic cleanup or retry of ambiguous writes. The source archive and independent receipts remain on owner-only storage; use encrypted storage at rest. Do not run against a live board or use it to establish private continuity without independent acceptance. The archive cap is conservative and may reject larger or symlink-based databases; no permission relaxation. Capture/restore CLI parameters: action, --confirm-owner-quiesced, --confirm-production-provenance, --company, --mission, --source-commit, --archive, --baseline (independently accepted qualification JSON), --proof (absent output path), and for restore --capture-proof. All private files mode 0600 in owner directories 0700. For remote archive transport use the separate owner snapshot client only after live authorized deployment. No actual production database has been located or restored by this change.
