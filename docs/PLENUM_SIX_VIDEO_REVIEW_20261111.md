# Plenum | Six full-caption video studies and free-first action decision
**11 November 2026 — Source review for Plenum Prometheus.** This report contains 73 platform/example mentions across six videos; duplicates are not separate installations. Original public YouTube descriptions and full text captions were accessed; original visual playback was not performed. Copyrighted transcripts are not republished.

## What is evidence, opinion, and the Plenum operating decision?
- **Original-source evidence:** Creator's own descriptions/chapters and public captions establish which products or examples are mentioned, not whether claims of cost, performance, scientific success or popularity are true.
- **Third-party expert analysis:** IBM's technical explanation of failure propagation and Jeff Su's short-reference rules are credible methods, but do not automatically prove that Plenum saves money or works faster.
- **Verified official vendor evidence:** Docling is MIT-licensed and processes structured PDFs; Consensus has a $0 tier with limited API/MCP use; OpenHands provides free local source and a limited cloud tier; Jan is an offline GUI needing owner hardware. Provider terms may change.
- **Our recommendation:** One original Chief plus relevant Research, Engineering and Verification specialists; a small source index, task-scoped skills and app rulebooks; free full-captions agent for public YouTube; retain original Ollama and avoid redundant desktop inference apps until a real computer exists.
- **Not established:** No paid account activated, no always-on private Paperclip/Hermes or WhatsApp host, no universal authenticated third-party browser, no owner-installed GPU workstation, and no independently reproduced engineering or biomedical outcome from the videos.

### Practical architecture extracted from IBM
- Plan, execute, store relevant memory and reflect
- Agent scaling increases latency, context and coordination costs
- Independent fact checking is separable from source retrieval
- Keep responsibilities narrow to limit cascading failure
- Do not split tightly coupled retrieval/ranking steps into separate agents
**Implementation:** Existing Chief routes a task; Research retrieves, Engineering builds, independent Goldfish checks. Do not make a second central Chief or stuff all agent roles with every tool and its entire history.

## Operating decision: facts before opinions
| Candidate | Creator's claim or pattern | Independent source or existing evidence | Plenum decision |
|---|---|---|---|
| More agents always speed work | IBM explicitly disputes unbounded expansion | Extra coordination/LLM calls add cost and cascading errors; existing Chief sometimes returned metadata-only or blocked tasks | **No new generic Chief**. Improve one genuine source-backed Research worker, then compare accepted results and human effort |
| Free transcript access | Video gives text, not necessarily API workflow | MIT `youtube-transcript-api` supports no-key caption retrieval; cloud IP limits may block | **Run bounded public captions worker** and report failures, no paid transcript API |
| All local AI is free | Upstream source can be free while GPUs/models/runtime are not | Current public GitHub Ollama/Qwen runs and no continuous owner VM evidenced | **Keep Ollama**; optional Docling on a real source parsing task, defer duplicate Jan/LM Studio/Open WebUI |
| Creator examples prove outcomes | Physical and medical success stories in NextWork video | Video anecdotes not original peer-reviewed studies or independent reproduced engineering | **Treat as design ideas**, verify scientifically before investor or grant claims |
| PDFs should always become Markdown | Jeff Su demonstrates reduced size and context | Complex math/tables and figures require original PDF preservation and page-layout verification | **Use source-preserving dual-index** for text-heavy documents; Docling only when structure needs it |
| Use APIs instead of browser for everything | Jeff Su calls it spare key | Our actual connected Gmail/Drive/GitHub actions already exist; other sites need owner permission | **Connected API first, browser when needed**, real account and appropriate authorization |

## 2026-11-11 | Genuine caption access failure and free no-key fallback
A real founder-issued original Research Director run for six videos, issue [#473](https://github.com/chadkhalil21-svg/Plenum-Scientific-Intelligence/issues/473), returned **0/6 public caption tracks** from the normal `youtube-transcript-api` on GitHub's public hosted network. The Action exited successfully because it accurately reported `CAPTION_UNAVAILABLE`; this is **not proof that any six videos lack captions**, and is **not an accepted working agent**.

We therefore added a single **anonymous Jina Reader** secondary provider using the exact documented public YouTube transcript-toggle method in https://github.com/jina-ai/reader/blob/main/cookbooks.md . Its Reader endpoint supports no-key calls within rate limits: https://jina.ai/en-US/reader/ . It receives only the public video ID/URL, with no private login, payment method or ChatGPT content. The original worker will try YouTube once, then anonymous Reader once. It extracts only clearly timestamped transcript sections and reports product names/time offsets, **never reproducing full copyrighted transcript text**.

The fallback must still earn actual status through a second founder-authorized GitHub issue and independent comment/artifact review. Until positive live caption retrieval is observed, source readiness is not continuous reliability. Existing interactive ChatGPT research already accessed full public text captions through a connected browsing provider; that access is not automatically available to GitHub Actions. Do not buy or silently spend trial credits for hosted transcript APIs.
