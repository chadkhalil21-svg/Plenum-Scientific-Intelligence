# Evidence-first efficient task execution

**Purpose:** minimize unnecessary computation while preserving scientific verification, user privacy and explicit consent for expensive operations. This optimization is an engineering improvement, **not AGI**.

## How to run from an iPad

GitHub → Plenum Research Control Center → Run workflow → operation **efficient**.

Only enter public scientific demonstration questions. The operation runs approved fixed-equation demonstrations; it does not invent or solve open-ended research answers.

- "Demonstrate thermal cooling" → one reviewed SciPy materials fixture.
- "Check orbital gravity and a circuit" → two reviewed fixtures.
- "Check an ethanol molecular formula" → one RDKit fixture.
- "Invent a universal physics law" → review required, no tools run.
- Queries marked confidential/private → review required, no tools run.

The saved report contains a SHA-256 hash of the question, not the question's text. Do not enter unpublished company patents, secrets, patient records, or credentials into public GitHub Actions inputs.

## What was removed

- The previous default scientific network could run four fixed scientific fixtures and an optional dependent OpenMDAO example for a narrowly focused question. This path selects just 1–3 relevant allowlisted fixtures using strict word boundaries and deduplication. A thermal-only question avoids **three of those four fixture calls**. This measures avoided task invocations, not a 75% runtime or cost reduction.
- Direct execution imports the existing verified SciPy lab only after preflight. No LangGraph, OpenMDAO, or language model is installed for this operation. Basic scientific dependencies are installed only for an approved matching fixture, and RDKit only when molecules are selected.
- Public research-memory is loaded only for the knowledge and discovery console operations, where existing code actually uses it.
- Complete repository CI and chemistry/biology source checks now run for pull requests and main-branch pushes rather than for every intermediate feature-branch commit as well. Superseded verification jobs may be canceled, and Python download caching is enabled.
- The old retrospective chemistry/biology AI challenge remains manual-only, avoiding wasteful reruns over already-inspected holdouts.

The operation is read-only, executes no generated Python, and reports failed fixtures without inventing outcomes. A dry-run computes a plan without invoking scientific tools.

## What remains intentionally heavier

Existing full research operations are unchanged. Novel research questions can require public literature, mathematical modeling, new empirical evidence, expert criticism, and separately approved, budgeted AI inference. A known orbit, cooling, kinetics, RC circuit, or ethanol fixture is NOT evidence for an unfamiliar scientific hypothesis.

The original independent experimental workflows and protected research-memory archives retain their own schedules and integrity safeguards. CI cancellation settings do not extend to their research audit jobs.

## Measure actual efficiency

Compare GitHub Actions timings before and after the update for Plenum Research Control Center, Verify Scientific AI Foundation, and Verify Real Chemistry and Biology Research Benchmarks. Report fields include approved tool count, unnecessary fixed-fixture calls avoided, model calls (always zero here), measured solver milliseconds, and known-model verification status.

Cost and wall-clock improvements must be measured rather than assumed. The guiding objective is **independently verified knowledge per unit of computation**, not the number of AI agents running.
