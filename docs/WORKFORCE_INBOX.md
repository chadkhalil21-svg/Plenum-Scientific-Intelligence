# Plenum Workforce | One Free Assignment Inbox

**Scope:** Public, nonsensitive tasks only. This is an ACTUAL input path to one approved existing research worker, not a universal autonomous company.

## How the founder uses it
In any chat with the connected GitHub app, ask Computer to **assign a public research task to the Plenum workforce**. Computer creates one issue in the existing `chadkhalil21-svg/Plenum-Scientific-Intelligence` repository:

Title: `[Plenum Workforce] public research`

Issue body:
```
PLENUM_PUBLIC_WORKFORCE_V1
objective: Review free open source AI agents and their security safeguards
```

Only an issue created by the exact founder GitHub account activates the workflow. No passwords, private business data, unpublished patents, customer information, or sensitive objectives may be put in this public repository. Any other request is refused.

## What actually happens
1. Existing GitHub Issues stores the original public instruction permanently. It is our initial **free task inbox**, not a new database.
2. The existing `world-horizon` research worker runs on a standard free GitHub Actions public-repository runner. We reused its original public-source adapters, without rebuilding browsing or the agent manager.
3. The new bridge checks the original report format, rejects reports claiming independent scientific discoveries and rejects an empty-source result. It posts a concise result or an honest blocker to the same issue. The source report is kept temporarily as an Actions artifact (seven days); the issue/comment status survives after the worker stops.
4. The Chief's original model-driven Deep Agents specialist delegation, n8n nine-role drafting agents, OpenHands, scientific engines and browser are **unchanged**. They remain available through their existing approved routes but are **not all callable by this first inbox**. This bridge does not pretend to coordinate the entire workforce.

## Existing business access — important boundary
ChatGPT already has connected GitHub, Render, Resend and other approved native provider tools where installed. It can work with them **directly in the chat, subject to consent and available tool permissions**. The connected app's credentials do **not** transfer into our GitHub Actions, n8n, Ollama or an arbitrary third-party browser. No production Google, Gmail, Stripe, Resend, customer, banking, or website credentials were copied, created or granted to this worker.

For any future genuine private app task: authenticate the specific provider from the user-controlled private runtime, limit permissions, use a secured credential store, ask before consequential sends/changes and verify the final provider state separately. Public Issues cannot carry confidential tasks.

## Free hosting and memory limitations
- GitHub Issues persists the public assignment and the final status; GitHub Actions responds to eligible issue events and already schedules existing public research agents. **This is event-driven, not continuously running compute.** Runner capacity is finite and schedules can be delayed.
- Existing LangGraph research has SQLite checkpoint support; the separate Chief prototype still uses temporary in-memory checkpoints. The inbox's durable issue is useful public task memory, **not** private long-running agent memory.
- Always-on private model workers need an owner-controlled host and encrypted storage; no suitable guaranteed zero-cost always-on capacity has been verified. We have not started a paid subscription or a production host.

## Additional free tools worth considering (not another framework installation)
- [NVIDIA SkillSpector](https://github.com/NVIDIA/SkillSpector) — **highest-value next optional adoption:** scan third-party agent skills for malicious instructions, data exfiltration and excessive permissions BEFORE importing them. Use local static mode `--no-llm` on nonsensitive public skills; a scanner is not a security sandbox.
- [Hermes Agent](https://github.com/NousResearch/hermes-agent) — useful **only** if we want a ready-made messaging/roster interface for named agents and scheduled conversations. Do not add as another competing Chief of Staff.
- [Superpowers](https://github.com/obra/superpowers) — useful software planning/checklist skill for OpenHands, not a new coding-agent engine.
- [Remotion](https://www.remotion.dev/) — useful for original marketing/tutorial motion graphics; confirm licensing and available rendering compute before adoption.
- [Airbyte](https://airbyte.com/) and [ClickHouse](https://clickhouse.com/) — later, when real marketing/sales data volume and authorised connectors justify a warehouse. **Do not install now.**
- [Freebuff](https://github.com/CodebuffAI/freebuff) — possible ad-supported auxiliary coding; free allowance and data handling must be reviewed before confidential source access.

**Success criterion for this exact bridge:** One founder-owned PUBLIC GitHub Issue starts an existing research worker without human website clicks, produces an actual source-linked result, and independently records a truthful completion or failure. This does not establish full workforce command, accurate source claims, autonomous account operations, 24/7 private hosting, or AGI.
