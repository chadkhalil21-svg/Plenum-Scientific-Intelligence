## What actually happens
1. Existing GitHub Issues stores the original public instruction permanently. It is our initial **free task inbox**, not a new database.
2. The existing `world-horizon` research worker runs on a standard free GitHub Actions public-repository runner. We reused its original public-source adapters, without rebuilding browsing or the agent manager.
3. The new bridge checks the original report format, rejects reports claiming independent scientific discoveries and rejects an empty-source result. It posts a concise result or an honest blocker to the same issue. The source report is kept temporarily as an Actions artifact (seven days); the issue/comment status survives after the worker stops.
4. The Chief's original model-driven Deep Agents specialist delegation, n8n nine-role drafting agents, OpenHands, scientific engines and browser are **unchanged**. They remain available through their existing approved routes but are **not all callable by this first inbox**. This bridge does not pretend to coordinate the entire workforce.

## Free hosting and memory limitations
- GitHub Issues persists the public assignment and the final status; GitHub Actions responds to eligible issue events and already schedules existing public research agents. **This is event-driven, not continuously running compute.** Runner capacity is finite and schedules can be delayed.
- Existing LangGraph research has SQLite checkpoint support; the separate Chief prototype still uses temporary in-memory checkpoints. The inbox's durable issue is useful public task memory, **not** private long-running agent memory.
- Always-on private model workers need an owner-controlled host and encrypted storage; no suitable guaranteed zero-cost always-on capacity has been verified. We have not started a paid subscription or a production host.
